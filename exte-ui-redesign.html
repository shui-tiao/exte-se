My take · 建议

如果只选一个

自用 / 团队内部工具：选 A，它最快、最省空间，落地成本也最低。 要上架给大众：选 B，它解决了「2FA 看起来很难」的信任问题。 面向开发者或作为专业版：选 C，它的记忆点最强。 也可以取 A 的骨架 + B 的秒数环：保留密度，同时让倒计时更容易读。

注：三稿都没有为了「好看」增加解释性文案，功能说明仍留在设置页。

三稿共有的底线

Not optional · 无论选哪一稿
01 / HIERARCHY

代码永远是第一视觉层

服务名与账户名服务于识别，验证码服务于任务。数字必须等宽、成组、无衬线干扰，6 位与 8 位都不跳宽。

02 / TIME

剩余时间不只靠颜色

进度线 / 秒数环 / 分段刻度都同时提供数值与形态，色觉障碍用户仍能判断；屏幕阅读器通过 aria-live 播报失效。

03 / FEEDBACK

点击即复制，且说清楚

复制后卡片短暂高亮 + toast，自动清除。HOTP 需要明确「已递增计数器」，避免用户以为复制失败。

04 / STATES

锁屏、空态、导入中同样被设计

锁屏不是一张默认表单；空态给出下一步；QR 读取失败要说明是「没找到码」还是「码不完整」。

05 / OFFLINE

字体不依赖网络

扩展没有网络权限，演示稿里的 Web 字体落地时需打包子集或回落系统栈；三稿都给出了可用的系统回退顺序。

06 / ACCESS

380 宽也撑得住 200% 缩放

列表使用弹性网格，服务名可截断、账户名可换行；所有图标按钮有 24px 以上命中区与可见 focus ring。
